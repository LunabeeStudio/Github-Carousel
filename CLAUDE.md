# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Chrome extension (Manifest V3) that turns screenshot tables in GitHub pull requests into a carousel with zoom. Plain JavaScript and CSS, no bundler, no dependencies, no build step.

## Development

- Load: `chrome://extensions`, enable Developer mode, then "Load unpacked" on the repo root.
- Reload after a change: click the reload icon on the extension card, then refresh the PR tab.
- Syntax check: `for f in src/*.js options/options.js; do node --check "$f"; done`
- No automated tests. Verify on a real PR (for example `LunabeeStudio/oneSafe6#651`), after both a direct load and in-app navigation from the PR list.
- Claude in Chrome cannot open `chrome://extensions`, so it cannot install the extension. To test without installing, paste `src/carousel.css` (as a `<style>`) and the three scripts into the PR page with `javascript_tool`, wrapped in one block with a `chrome.storage` stub.

## Architecture

- `manifest.json` injects `src/settings.js`, `src/carousel.js`, `src/content.js` (in that order) and `src/carousel.css` on all of `https://github.com/*`. These are classic scripts sharing one isolated world: `settings.js` defines `GHCSettings`, `carousel.js` defines `GHCCarousel`, `content.js` uses both.
- `src/content.js`: gates on the PR path, scans `.markdown-body table` for screenshot images, inserts the trigger button, intercepts image clicks, and rescans on DOM changes.
- `src/carousel.js`: the overlay. Builds slides from parsed rows, handles zoom, pan, pinch, sync zoom, keyboard, and the thumbnail strip. The overlay DOM is created on first open.
- `src/settings.js`: `{ mode, sync, keep }` in `chrome.storage.sync`, shared by the content scripts and `options/`.
- The design came from a prototype artifact (https://claude.ai/artifact/WepSKK2vZNCdg4rdNgVE6h). Keep behavior in line with it unless the user asks otherwise.

## GitHub page constraints

- Match all of github.com, not `/pull/*`. GitHub navigates without full reloads (Turbo and React), and Chrome injects content scripts on full loads only. `content.js` checks `location.pathname` itself.
- Rescans come from a debounced `MutationObserver` plus `turbo:load` and `popstate`. `data-ghc` on a table marks it as processed, so a rescan never adds a second button.
- Rendered tables sit inside `<markdown-accessiblity-table>` (GitHub's spelling). Insert the trigger before that wrapper.
- Real screenshot tables vary. Some have a `Before | After` header row. Others (like the ones generated by the `gh image` workflow) have no `<thead>`, a single row with many images, and the caption in a `<sub>` inside the same cell. A cell's caption is its column header, else its own text. Tables with more than 4 images in a row (`MAX_ROW_PANELS`) open in one-image mode.
- Images are private signed URLs (`private-user-images.githubusercontent.com`, short-lived JWT) wrapped in an `<a>` to the same file. Read `img.currentSrc || img.src` when opening; never cache or rebuild the URL.
- Image clicks are intercepted in capture phase. Modified or middle clicks keep opening the raw file.
- While the overlay is open, a capture-phase `keydown` listener on `window` stops propagation, so GitHub hotkeys (`s`, `/`, `t`, `.`) do not fire.
- The trigger button uses Primer CSS variables with fallbacks. The overlay uses its own dark palette, scoped to `.ghc-overlay`.
